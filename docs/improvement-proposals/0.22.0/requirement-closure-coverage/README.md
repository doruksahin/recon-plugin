# Retain requirement-closure coverage

> Retain and resume bounded requirement-closure evidence by durable ID.

- **Status:** release candidate (v0.19.0)
- **Release candidate:** [PR #2](https://github.com/doruksahin/recon-plugin/pull/2), merged as [`321514d`](https://github.com/doruksahin/recon-plugin/commit/321514df18e487c64ef17cbcaea974c99722e89c)
- **Priority:** P1
- **Theme:** determinism rail
- **Origin:** ATT-4845 scored replays, 2026-08-04 — three production-valid
  BLOCKED submissions each retained 1/3 scorer coverage before their temporary
  replay paths could disappear.
- **Depends on:** decision-closure-triage

## Problem

The current replay lab has immutable per-run evidence, but its temporary run
path is the handoff. A later improvement session must reconstruct baselines,
candidate status, required controls, and safe next action from chat memory.
That makes an improvement conclusion fragile and encourages a claim before a
candidate replay exists.

three ATT-4845 scored runs

## After (proposed)

```text
python3 tools/improvement-cycle.py state \
  docs/improvement-proposals/0.22.0/requirement-closure-coverage
state: AWAITING_CANDIDATE
candidate_brief: docs/improvement-proposals/0.22.0/requirement-closure-coverage/candidate-implementation-brief.md
next_action: implement the candidate from the retained brief; then capture one fresh candidate run for attempt 1
```

The rail retains only `receipt.json`, `submission/triage.yaml`,
`evaluation/result.json`, `evaluation/score.txt`, and a checksum manifest
under `evals/evidence/`; neither a target repository nor an oracle is copied.

## Authored calibration and claim boundary

The scorer’s immutable historical result remains 1/3. A separate human
calibration found two atomic fallback decisions in the current submissions, so
the meaningful atomic interpretation is 2/4. This proposal neither rewrites
nor rescored the old results. Its target is 4/4 atomic decisions. Its required
negative control is a fully specified ticket that remains READY.

No cross-task, cross-model, or cross-host quality claim is made. Attempt 2 was
accepted for the declared frozen target and READY control only: three target
runs retained the expected BLOCKED disposition with 3/3 scored decision
coverage, while three same-candidate controls remained READY/PASS with no
blockers. This does not establish broader triage quality or release quality.

## Implementation sketch

- `iteration.yaml` is the machine-owned capture index and fixed milestone contract.
- `comparison-rubric.yaml` fixes the bounded semantic review contract by ID and hash.
- `candidate-implementation-brief.md` is the exact no-chat-history implementation handoff.
- `tools/improvement-cycle.py` captures, verifies, derives, persists comparisons
  and reviews, opens immutable retry attempts, and renders.
- Repository-only `recon-improvement-loop` starts from derived state and gives a
  fresh session a short copy-ready handoff.
- `improvement-report.html` is generated by the rail and byte drift-checked.
