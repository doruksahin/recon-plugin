# Version-scoped team review laboratory implementation plan

**Origin:** Recon v0.19.0 rollout planning on 2026-08-05. The operator wants
teammates to review local dossiers for many Jira tickets without Jira comments,
then synthesize feedback and route only evidenced themes into Recon changes.

**Governing design:**
[SPEC-01KZ7E7FXK0T0W83PKGWPMC0ZW](../../decree/spec/reliability/evidence/spec-01kz7e7fxk0t0w83pkgwpmc0zw-recon-version-scoped-team-review-laboratory.md).

## Delivery sequence

1. Establish the external version tree, schema, semantic templates, and
   repository-local operator skill.
2. Implement the fail-closed CLI lifecycle and immutable minimal captures.
3. Add complete isolated clean/fault controls and make them universal through
   the coherence gate.
4. Add short root and nested `AGENTS.md` routers that link to owners rather than
   duplicating fields or state rules.
5. Add the v0.23 planning record and extend the generated system map with the
   version-review layer.
6. Run focused tests, generated-view checks, Decree intent/lint/progress, and
   the full pre-commit guardrail.
7. Move canonical source ownership to `AdCreative-ai/recon-plugin`, retain
   `doruksahin/recon-plugin` as its public personal fork, and bind live review
   evidence to a distinct private GitHub repository whose identity and
   visibility the rail verifies before every write.

## Claim boundary

Synthetic controls may establish deterministic rail behavior only. Do not call
the team-review workflow effective until at least three private real-ticket
dossiers from one plugin version receive independent reviews and retained
consensus. Any Recon behavior change still requires sanitized replay cases,
negative controls, comparison, and semantic acceptance through the existing
improvement loop.
